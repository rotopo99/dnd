# Спека: сетевой кооператив (WebRTC без сервера)

Дата: 2026-11-15. Статус: проект. Канону не противоречит (правила боя/мира не меняются, добавляется только транспорт).

## Цель для игрока
Пройти Руслании вместе с друзьями: каждый ведёт своего героя, общий бой, общая карта, общий кринж в чате. Без регистрации и сервера: обменялись двумя строками в мессенджере и играете.

## 1. Режим
| Параметр | Значение |
|---|---|
| Игроков | 2–4 (хост + до 3 гостей) |
| Герой | у гостя свой: создаётся и хранится у него локально, при входе отправляется хосту (`hello.hero`, нормализованный save-формат героя) |
| Хост | авторитет: держит save, мир, бой, RNG, сцену |
| Гость | шлёт намерения (команды), получает снапшоты/события; своего save мира не пишет |
| Напарники-NPC | у хоста; принадлежат хосту |
| Версия | `GAME_VERSION` + `SAVE_VERSION` + `PROTO` в hello; несовпадение — отказ с сообщением «Версии игры отличаются: у вас X, у хоста Y» |

Прогресс героя гостя (опыт, лут, квесты) хост возвращает в `heroSync` в конце боя/узла; гость сохраняет героя у себя. Один слот героя = один игрок (`slot` 0..3, слот 0 — хост).

## 2. Синхронизация
| Область | Метод |
|---|---|
| Бой | детерминированный: хост шлёт `battleStart {seed, setup}` (аргументы `createBattle`, составы, карта); далее только `cmd {turn, actor, action}` в порядке хоста. Все клиенты применяют одну и ту же `rules/`-функцию. Раз в ход (конец раунда хода) каждый шлёт `hash` (32-bit FNV от канон. сериализации состояния); при несовпадении хост шлёт `fullState` целиком и гость заменяет локальное состояние |
| Мир/карта/узлы | хост шлёт `snap` (сцена, id узла, позиции партии, открытые модалы-лента) на событие + дельты `delta` по изменению; гость рисует то же |
| Свободная карта | каждый двигает своего героя: гость шлёт `move {x,y,dir}` 10 Гц, хост валидирует (скорость, стены) и рассылает `pos` всех 10 Гц; интерполяция на клиенте |
| Диалоги/выборы | сюжетный выбор — **решает хост** после «совета»: гости шлют `vote {optId}` (видны как метки у вариантов), хост подтверждает любым вариантом. Личные (романс, торговля, навыки героя) — решает владелец героя |
| Торговля/инвентарь | у каждого свой рюкзак и деньги; торговля идёт между героем и NPC, хост считает цену и результат, шлёт `heroSync` |
| Лут | раздел: после боя/сундука каждый предмет — «взять/пас» (`lootRoll`), побеждает бросок d20 (ничья — перебросить), мораль/деньги делятся поровну; хост может «раздать вручную» |

## 3. Чей ход в бою
Актор — герой игрока → ходит его владелец (хост валидирует `cmd.actor` против `owner`). Напарники-NPC, враги, окружение — хост. Таймер хода игрока: 60 с, по истечении — хост делает «пропуск» (настройка лобби, 0 = без таймера). Отключённый игрок: его герой на авто-ИИ хоста до переподключения.

## 4. Сеть
- ICE: `stun:stun.l.google.com:19302` по умолчанию (поле «STUN-сервер» в настройках, можно сменить/очистить). STUN — не сервер игры: он лишь подсказывает вашему браузеру внешний адрес для пробития NAT, игровые данные через него не идут.
- Подсказка игроку в окне создания: «Без STUN игра работает только в одной локальной сети (Wi-Fi). Через интернет STUN нужен».
- TURN нет. При неудаче (таймаут 20 с / `failed`) сообщение: «Не удалось соединиться напрямую. Бывает за строгим NAT/корпоративной сетью/некоторыми мобильными операторами. Попробуйте: другую сеть или точку доступа с телефона, отключить VPN, другой браузер, или играть в одной Wi-Fi сети».
- Сжатие кода: JSON `{v, type, sdp, ice}` -> `CompressionStream('deflate-raw')` -> base64url; префикс `RSL1.`. Ждать `iceGatheringState=complete` (до 5 с), чтобы все кандидаты были в одной строке; без trickle ICE. Цель — одна строка до ~1500 символов (чат-мессенджер); из SDP выкидываются лишние строки (`a=extmap`, `a=rtcp-fb`, кодеки — DataChannel-only). Нет `CompressionStream` — fallback на несжатый base64url + предупреждение.

## 5. UI
- Главное меню: «Сетевая игра» → «Создать» / «Присоединиться» / «Назад».
- **Создать (хост)**: шаг 1 — «Ваш код» (поле только чтение + «Копировать», счётчик символов); шаг 2 — поле «Вставьте код ответа» + «Соединить»; для 2-го и далее гостей кнопка «Добавить игрока» повторяет цикл.
- **Присоединиться (гость)**: поле «Вставьте код хоста» → «Принять» → показывает «Ваш ответ» + «Копировать» → ожидание хоста.
- Ошибки кода: «Код повреждён/не от этой версии» без вылета.
- **Лобби**: список игроков (имя, класс, ур., слот, пинг, цвет), статус соединения (ожидание / соединено / потеряно), хост выбирает сцену старта/продолжает партию, кнопка «Готов», хост — «Начать»; «Кикнуть».
- **Чат**: окно внизу слева, до 200 символов, последние 50 строк, Enter — писать; в бою/мире сворачивается до последних 3 строк, исчезающих через 8 с.
- **Индикатор хода**: в бою плашка «Ходит: <имя> (<игрок>)» цветом игрока; у чужого хода ваши кнопки действий неактивны с подсказкой «Ход игрока X».
- Цвет-метка игрока (4 цвета из STYLE) у портрета и ника.
- **Переподключение**: при `disconnected` — плашка «Связь потеряна» + «Переподключиться» (новый обмен кодами, как в лобби); хост сохраняет слот и героя 10 мин сессии, гость вставляет `slot`+токен в hello (`rejoinToken`), получает fullState.
- Звук: короткие сигналы входа/выхода/сообщения (sound-designer).

## 6. Протокол
Канал: один `RTCDataChannel` `game` (ordered, reliable); сообщения — JSON-строки `{t, n, ...}` (`n` — счётчик). Лимит сообщения 64 КБ, большие (fullState, hero) режутся на `chunk {id,i,of,data}`.
| t | Направление | Поля |
|---|---|---|
| hello | G→H | proto, gameVer, saveVer, name, hero, rejoinToken? |
| welcome | H→G | slot, token, players, settings |
| reject | H→G | reason (`version`/`full`/`busy`) |
| lobby | H→all | players[{slot,name,ready,connected}], settings |
| chat | any | text (хост ретранслирует, ставит slot) |
| battleStart | H→all | seed, setup |
| cmd | G→H, H→all | turn, actor, action {type,target,item?...} |
| hash | all→H | turn, h |
| fullState | H→G | state (chunked) |
| snap / delta | H→all | scene, node, state / patch |
| move / pos | G→H / H→all | x,y,dir / [{slot,x,y,dir}] |
| vote | G→H | promptId, optId |
| lootRoll | G→H | itemId, choice |
| heroSync | H→G | hero (патч) |
| ping/pong | any | ts |
Частоты: `pos` и `move` 10 Гц, ping 2 с, остальное по событию. Трафик: <5 КБ/с в мире, всплески при fullState (~50–200 КБ).

## Правила: числа для balance-tester
| Параметр | Значение |
|---|---|
| Игроков макс. | 4 |
| Таймер хода игрока | 60 с (0 = выкл) |
| Таймаут соединения | 20 с |
| Сжатый код | цель ≤ 1500 симв. |
| Хранение слота при обрыве | 10 мин |
| Масштаб врагов в бою | по числу героев (формулу даёт balance-tester; старт: ×(героев+NPC)/(базовый состав)) |
| Масштаб врагов (реализовано, этап 2) | +`NET.extraPerHero` = 1 враг на каждого героя сверх первого, враги берутся по кругу из списка встречи (`net/coop-battle.js scaleEnemies`). Тренировочный бой: `ENCOUNTERS.standard1` + (героев − 1). Точные числа — balance-tester (`data/net.js`) |

## 7. Этапы
1. **Соединение + чат + лобби**: `net/` (rtc, codec, protocol), меню, обмен кодами, список игроков, чат, проверка версии.
2. **Совместный бой**: `battleStart`, `cmd`, хэш-проверка, fullState, чей ход, таймер, лут-раздел.
3. **Совместный мир**: карта, узлы, свободная карта (`move/pos`), диалоги/голосование, торговля, `heroSync`.
4. **Переподключение и сохранения кооп-партии**: rejoinToken, save кооп-партии у хоста (список игроков и привязка героев по имени/слоту), гость сохраняет своего героя.

## 8. Тестирование без двух машин
Playwright: один браузер, два контекста/страницы (`browser.newContext()` x2; для мира достаточно и одной вкладки в одном контексте). Страницы вызывают `window.__net` (хуки: `createOffer()`, `acceptOffer(code)`, `acceptAnswer(code)`), скрипт переносит строки между страницами через `page.evaluate`. В loopback STUN не нужен (`iceServers: []`). Сценарии: коннект, чат, бой 2 героя (сравнить хэши), намеренная порча состояния -> fullState, обрыв (`pc.close()`) и реконнект, несовпадение версии -> reject. Тест — `tools/playtest-net.mjs`.

## Критерии приёмки
1. Код хоста и ответа — одна строка с префиксом `RSL1.`, обмен двумя вставками даёт статус «Соединено» на обеих страницах за ≤ 20 с (loopback).
2. Версии не совпали -> гость видит сообщение, лобби не заполняется.
3. Бой на 2 игрока: хэши совпадают каждый ход; чужой герой на чужом ходе кнопки не активны.
4. Порча состояния гостя восстанавливается `fullState`, без ошибок консоли.
5. После обрыва гость возвращается в свой слот с тем же героем.
6. Без сети игра/одиночный режим работают как раньше.

## Вне рамок
Свой/TURN-сервер, матчмейкинг, PvP, голосовой чат, зрители, >4 игроков, чит-защита сверх валидации хоста, смена хоста в игре, кроссверсионная совместимость.
