# Спека: переход 3D-графики на Three.js

Решение человека (2026-11-17): графика — Three.js (+ Blender для моделей), свой WebGL2-рендер `game/src/gfx/*` заменяем.
Логика (rules/, world/, scenes/, весь UI на Canvas 2D) не меняется. Предыдущая спека — `docs/specs/3d.md` (читаемость,
критерии «глаза не режет» §7 остаются в силе), стиль — `docs/STYLE.md`, пост — `docs/research/premium-look.md`.

## 1. Подключение
- `game/vendor/three/` — `three.module.js` + `three.core.js` (0.187.0) и `addons/` (только нужное: GLTFLoader,
  SkeletonUtils, BufferGeometryUtils, EffectComposer, RenderPass, ShaderPass, OutputPass, UnrealBloomPass, GTAOPass +
  их шейдеры); `game/vendor/three-vrm/` (3.5.5, min). Лицензии MIT рядом, состав — `game/vendor/README.md`.
  pmndrs `postprocessing` не берём: хватает аддонов Three.
- `game/index.html`: importmap `three` → `./vendor/three/three.module.js`, `three/addons/` → `./vendor/three/addons/`,
  `@pixiv/three-vrm`. Пути относительные — работает с любого статичного хоста и из подпапки.
- `main.js` грузит бэкенд **динамическим** `import('./three/engine.js')`: статический граф модулей не тянет `three`
  (node-тесты, `editor.html` без importmap). Не загрузилось — 3D рисует старый рендер, предупреждение в консоль.

## 2. Архитектура
- Слои: `#gl` (старый WebGL2), `#gl3` (Three.js), `#game` (Canvas 2D UI, ввод) в одной ячейке грида; виден только слой,
  рисовавший в этом кадре. Мир обрезается областью карты через CSS `clip-path` (пост-обработка идёт по всему кадру).
- Настройка «Движок 3D: Three.js / старый» (`gfxPrefs().engine`, по умолчанию `three`; `?engine=old|three` в URL).
  Режим 3D/2D — как раньше (`gfxMode()`).
- Бэкенд-независимая часть кадра — `gfx/scene3d.js prepFrame`: камера (твины, juice `cam.fx`), высоты юнитов, оверлей
  `ob` (подсветки, путь, зоны, поверхности, кольца, пятна контакта, ламп-пятна, крышки среза), частицы `PARTS`, render
  on demand, экземпляры юнитов (шаблон, поворот, шаг, альфа, вспышка, цвет команды). Старый рендер — `renderOld`,
  новый — `three/battle.js`. Состояние боя не знает о бэкенде (детерминизм коопа).
- Камера: игровая `gfx/camera.js` остаётся источником правды (вращение 90°, зум 3 уровня, панорама, фокус). Three-камера
  — `OrthographicCamera`, собранная из `ortho(cam)` (тот же базис и пиксели на метр): 2D-якоря (`cellScreen`,
  `unitScreen`), старый аналитический пикинг и картинка совпадают. Перспектива с узким FOV (как Divinity) — этап 4,
  после переноса якорей 2D на `Vector3.project`.

## 3. Сущности → объекты Three
| Игра | Three |
|---|---|
| клетки, высоты, стены, укрытия, реквизит карты, объекты узла | статичные чанки 8×8 (`buildChunk` → `BufferGeometry`), пересборка изменившегося чанка |
| стены края карты | 2 меша на группу сторон: полный / низкий (ближние к камере стороны) |
| горизонт | `buildBackdrop`: земля — прозрачный меш, силуэты — только дальние стороны |
| бочки | пул мешей по `b.barrels` |
| юниты | `SkinnedMesh` на шаблонах `units3d` (этап 1) → GLB/VRM (этап 3) |
| подсветки, путь, зоны, поверхности, кольца | один динамический прозрачный меш-декаль на полу (polygon offset) |
| эффекты, погода | instanced-частицы (`ShaderMaterial`), декали — в общем оверлее |
| пикинг | `Raycaster`: прокси-цилиндры юнитов + невидимая поверхность (верх клетки по `topAt`, бока высоких клеток) |

## 4. Материалы
- Окружение: `MeshStandardMaterial` на вершинных цветах (линейные из палитры, запечённый AO), `onBeforeCompile`:
  value-noise в мировых координатах на альбедо/шероховатость, светящиеся вершины → эмиссив (bloom), срез стен
  («Обзор»: discard выше пола+cutH в коробках перед фокусом; тени не режутся). Этап 4: PBR-карты из Blender (GLB).
- Персонажи: `MeshToonMaterial` (ступени `GFX.three.unit.steps`), эмиссив визоров, вспышка удара — `emissive`;
  контур — inverted hull (`BackSide`, рост по скиннутой нормали, цвет команды); рентген за стенами — тот же скелет,
  `GreaterDepth`, рисуется в непрозрачном списке до тел (`renderOrder`). Этап 3: собственный тун-`ShaderMaterial`
  (SDF-тень лица, rim, Kajiya-Kay волос), атлас лиц.
- Цвета — только палитра STYLE; новые — через арт-директора.

## 5. Свет и пост
- Свет: `DirectionalLight` ключ (направление `GFX.shadow.dir` относительно камеры, тени PCF, ортокамера тени по коробке
  карты — не «плавают»), заполняющий (`GFX.fill.dir`), `HemisphereLight`. Ночь/сумерки — приглушение + до 8
  `PointLight` по `lightSources` (пул создаётся при первой ночи). Туман — линейный `Fog` цвета биома.
- Пост (`EffectComposer`, HDR HalfFloat, MSAA 4 на железе): Render → GTAO → UnrealBloom (порог выше палитры — светится
  только эмиссив) → Output (Neutral tonemap: сохраняет циан/мадженту, `exposure` × яркость) → Grade (виньетка по
  области карты, баланс биома ≤ 3 %, потолок пиксела). «Снизить эффекты» — без поста, тумана, теней.
- Программный GL (SwiftShader/llvmpipe): без bloom и GTAO, тени ×0.5 (`GFX.three.soft`); `?hq=1` — полное качество.
- Juice: тряска/акцент-зум через `cam.fx` (камера), хит-стоп через `S.vtime` — как раньше.

## 6. GLB / VRM (этап 3)
- `GLTFLoader` с общим кэшем по URL (Promise), экземпляры — `SkeletonUtils.clone`, анимации — `AnimationMixer` на юнит,
  клипы из Blender (idle/walk/attack/hit/death/cast). Модели — `game/assets/models/*.glb` (скрипты `tools/blender/`).
- VRM: `@pixiv/three-vrm` (`VRMLoaderPlugin`), spring bones — `vrm.update(dt)`, выражения лица — эмоции `d.emo`.
- Шаблон юнита → ключ модели (класс/раса/враг) в `data/`; нет модели — процедурный шаблон.

## 7. Производительность
- Цель: 60 fps на встроенной графике. Статика — чанки, culling по коробке чанка; общие геометрии (шаблоны, реквизит)
  в кэше движка; материал мира один на бой. Этап 4: `InstancedMesh` для мелочи/реквизита, LOD шаблонов (есть `lod`),
  `BatchedMesh` для объектов узла.
- Render on demand как прежде (15 fps простоя, 6 на программном GL).
- `dispose` при смене сцены (`leaveScene` → `dropBattle3d` → `dropBattleThree`): геометрии чанков, текстура высот,
  материалы юнитов, пост-цепочка; потеря контекста > 2 с → 2D + тост.

## 8. Фолбэк
Нет WebGL2 / ошибка → 2D. Three.js не загрузился или не создал рендерер → старый рендер. Потеря контекста Three > 2 с →
2D (`markGfxBroken`) + тост.

## 9. Этапы
1. **Бой** на Three.js за флагом (сделано): поле, юниты-шаблоны, декали, пикинг Raycaster, камера, свет+тени, пост.
2. **Свободная карта узла** (`roam3d`) на том же бэкенде (`prepFrame`-аналог для roam, конусы, NPC, погода, день/ночь).
3. **Персонажи из GLB/VRM** (Blender), тун-шейдер персонажей, лица, анимации миксером.
4. **Пост и полировка**: PBR-карты окружения, GTAO на орто (подбор), перспективная камера (опция), инстансинг, LOD,
   автоподстройка качества, скриншот-регрессия 3 сцен.
5. **Удалить старый gfx**: `gl.js`, `post.js`, `renderOld`, шейдеры; `mesh.js`/`models.js`/`env3d.js` остаются как
   генераторы геометрии, пока их не заменят GLB.

## Риски / открытые вопросы
- GTAO на ортокамере даёт слабый эффект (проверено в SwiftShader `?hq=1`) — подобрать радиус/толщину на железе или
  взять SAO/SSAO.
- Inverted hull на тонких конечностях даёт полоски контура поверх тела — как в старом рендере; лечится экранным контуром
  (этап 4) или моделями.
- Размер vendor: three ≈ 2.1 МБ без минификации (сборки нет) — кэшируется браузером.
