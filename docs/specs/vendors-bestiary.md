# Спека: индивидуальные торговцы и бестиарий/кодекс

Данные: `game/src/data/items/vendors.js`, `game/src/data/text/codex.js`. Движок и сцены — за программистами.
Взаимодействует с: репутацией (`reputation.js`), лавкой (`shop.js`, `shopPrices`), сохранением (`save.met`, `save.flags`), лутом (`world/loot.js`), `data/effects.js`, `data/surfaces.js`, `LOCATION_LORE`, `npcs.js`.

---
## Часть 1. Торговцы: у каждого NPC свой товар

### Цель для игрока
Лавка перестаёт быть «одной на фракцию»: к оружейнику идёшь за стволом, к бронику за шкурой, к аптекарю за бинтами. Фирменную вещь можно найти только у конкретного человека, и ради неё стоит пройти полкарты и подружиться.

### Правила
Профиль — `VENDORS[npcId]` (142 записи: все NPC с услугами `trade`/`train` + 3 density-NPC без `trade`, у которых `addTrade: true`). Специализация — `ARCHETYPES[arch]` (12 штук). Лавка NPC заменяет `SHOPS[faction]`/`factionStock`; для узла без торговцев остаётся прежняя лавка узла.

**Ассортимент (собирает `shop.js`, детерминированно):**
1. **Потолок ступени** `cap = tierCap(lvl)`, `lvl` = `vendor.lvl` или `REGIONS[LOCATIONS[npc.location].region].levels[1]`. Предмет доступен, если `item.tier <= cap`.
2. **Staples** архетипа — всегда в продаже (качество «рабочее»).
3. **Фирменное** `sig`: строка — эксклюзив (id нигде больше не продаётся и не падает в пулах), `{id, q:'masterwork'}` — «издание» мастера. Гейт по репутации к фракции NPC: `item.tier - cap <= 0` — нейтрально, `1` — «Дружелюбны», `>=2` — «Союзники». Для `none`-NPC — по отношению к фракции узла. Не прошёл гейт — строка в лавке серая «<тир>: нужна репутация».
4. **Ротация**: слоты `ROTATION.sizes[size]` (S 5, M 8, L 11) минус staples и sig. Заполняются выборкой из пулов `ARCHETYPES[arch].tiers[1..cap]` без повторов, вес ступени `cap` — 3, `cap−1` — 2, ниже — 1; запрещённое `FACTION_BANS[faction]` (тип оружия, `kind:*`) исключается. Seed = `hashSeed(npcId + ':' + floor((day−1)/restock))`; `restock` — дней до смены (`vendor.restock`, по умолчанию 4, у бродяг 1–3, у ключевых 5–6). `exodusSync`/`passDays` двигают день — сток меняется сам.
5. **«Ходовой» товар**: с шансом `rareChance` (0.3, тот же seed) добавляется 1 предмет ступени `cap+1` по цене ×`rareMarkup` (1.3).
6. **Хлам**: у архетипа `junk` (и `scavengers`) доля `junkShare` ротации идёт качеством «хлам» (×0.4 цены, как в `QUALITY`).
7. **Мини-торговцы** (без `sig`): авто-издание — 1 предмет оружия/брони/мода из пула ступени `cap`, качество «мастеровое» (×2.5); поле `ed` — явный список взамен авто-выбора (`[]` — без издания).
8. **Наставники** (`mentor: true`): лавка размером ≤ S (5), открывается кнопкой «Купить у наставника» рядом с «Учиться»; услугу `trade` программист не добавляет — достаточно профиля. Скидка на обучение: «Дружелюбны» −10 %, «Союзники» −20 %.

**Цена покупки** = `item.price × QUALITY[q].price × arch.markup × (1 + vendor.greed) × repMult × mult*` , где `repMult`: подозрение +25 %, нейтрально ×1, дружба −10 %, союз −20 % (как в `items.md`), `mult*` — существующие множители (исход, навыки/ХАР, торг).
**Цена продажи** = `item.price × arch.sellRate × (loves ? 1.25 : 1)`; `buys` — категории, которые берёт (`weapon|armor|mod|consumable`); вне `buys` и вне `loves` лавка не берёт. `loves`: `cat:<cat>`, `kind:<kind>`, `type:<type оружия/брони>`, `group:<melee|ranged|special>`. Реликты не покупаются (как раньше).
**Характер** — только `greed`: −0.10 (щедрый: Паракетамол, Кашевар) … +0.20 (жадный: Гвоздарь, Квитанция, Брошка).

### Таблица чисел (крутит balance-tester)
| Параметр | Значение | Где |
|---|---|---|
| Потолок ступени по `levels[1]` региона | ≤3→1, ≤5→2, ≤9→3, ≤14→4, иначе 5 | `TIER_CAP` |
| Слоты ротации S / M / L | 5 / 8 / 11 | `ROTATION.sizes` |
| Дней до ротации | 4 (1–6 по NPC) | `restock` |
| Шанс «ходового» / наценка | 0.3 / ×1.3 | `ROTATION` |
| Доля хлама у барахольщиков | 0.5 | `ROTATION.junkShare` |
| Наценка характера | −0.10…+0.20 | `greed` |
| Любимое при продаже | ×1.25 | правила |
| Мастеровое издание | ×2.5 | `QUALITY` |
| Эксклюзивов | 90 id у ключевых торговцев (2–4 фирменных) | `sig` |

### Состояния и события
- Состояние лавки: `save.flags['shop:<npcId>:<day>']` (как сейчас). Покупка уникального/эксклюзива не убирает его с полки (бесконечный, цена та же).
- Вход: `location.js` → «Торговля» у NPC → `openShop(game, { title, vendor: VENDORS[id], …})`; `addTrade` — NPC получает услугу `trade` в `npcs.js`/`density-npcs.js` (список: `d-vasya`, `d-kotelok`, `d-gudok`).
- Событие «стигма» (`cult`: `cyber-blade`, `verdict-scythe`) и запреты `FACTION_BANS` сохраняются.

### UI/фидбек
- В шапке лавки — одна строка `note` NPC и бейдж специализации (`ARCHETYPES.name`); у фирменного — золотая метка «Фирменное» (эксклюзив) / «Мастерская работа» (издание).
- Внизу — «Обновление через N дн.» (`restock − (day−1) % restock`); тост «Новый товар» при заходе после ротации.
- Скидка/наценка видна в подсказке цены (`price` × репутация × характер).
- Звук покупки — как есть; редкий товар — отдельный «дзынь» (если у звукорежиссёра найдётся).

### Критерии приёмки
1. Каждый NPC из `npcs.js` с услугой `trade` или `train` имеет запись в `VENDORS` (скрипт `import`-проверки; сейчас ошибок 0).
2. У двух торговцев одного региона ассортименты различаются; эксклюзив (`sig` строкой) не встречается ни в чьём пуле и ни у кого другого.
3. Ассортимент не меняется при повторном входе в тот же день и меняется после `restock` дней.
4. Предмет ступени выше `cap` купить нельзя (кроме фирменного по гейту репутации и «ходового»).
5. У Кузнеца Окалины нет энергооружия/кибер-клинков, у Архивариуса Девятого нет опиатов и кринжа.
6. Все `id` предметов существуют в `GAME_DATA.ITEMS`.

### Вне рамок
Количество товара/остатки на складе, торг между NPC, караваны, импланты как отдельные предметы (в данных нет — «кибер» = энергооружие, дроны, кибер-клинки), ремонт и крафт по заказу, разные цены у разных городов одного торговца.

## Часть 2. Бестиарий и кодекс

### Цель для игрока
Мир ощущается узнаваемым: встретил — запомнил, победил — понял, победил много раз — освоил. Кодекс — дневник открытий, а не справочник «всё сразу».

### Правила
**Разделы:** Бестиарий (по фракциям), Фракции, Места, Персонажи, Термины (`CODEX_SECTIONS`).

**Уровни записи врага** (ключ — `baseId(enemyId)`, версии `^…`/`-l8` и т.п. делят запись с базовым типом, если есть `ENEMY_LORE`; иначе своя запись по id):
| Уровень | Условие | Открывается |
|---|---|---|
| Видел | враг участвовал в бою или назван в диалоге/записке | имя, портрет (`enemySubject`), фракция, `ENEMY_LORE[id].lore` |
| Побеждён | ≥1 победа над ним (убит/«Сломлен») | ЗДР, КБ, МРЛ, список способностей с подсказками |
| Изучен | ≥5 побед над этим типом | слабости/сопротивления (`resist`, `immuneStatus`, теги, `vulnMul`), таблица лута (`LOOT_TABLES`, шансы словами), `xp` |
| Находка | флаг `cx-*` в `save.flags` | доп. абзац из `finds` (врага) или `FACTION_FINDS` (фракции) |

Счётчики: `save.codex = { seen: {id: true}, kills: {id: n}, flags: [] }`. Флаги находок — обычные `save.flags['cx-…']`, ставятся: запиской (`event`/`cache`: `flags`), диалогом, квестом. Схема: `{ flag, text }` в `finds`/`FACTION_FINDS`; сценарист привязывает флаги к реальным источникам (список текущих — в `codex.js`; к моменту реализации источников нет, записи остаются закрытыми).

**Остальные разделы:**
- **Фракции**: открыты, если `isMet(save, f)`. Текст — `FACTION_LORE[f]`; ниже — отношение (тир репутации), столица/места, основные враги (из бестиария, только открытые), торговцы (только встреченные NPC), находки `FACTION_FINDS`.
- **Места**: узлы из `save.visited`; описание — `locationLore(id)` (`LOCATION_LORE`), без «беды-крючка» до события.
- **Персонажи**: NPC, с которыми говорил (`save.npcs[id]`); карточка из `npcs.js` (`role`, `character`, `bark`), без `hook`; `cameo` и скрытые ключевые — не показывать, пока не встречены.
- **Термины**: статусы из `STATUSES` (имя + `desc`) и поверхности из `SURFACES` (имя + `desc` + `interacts`) — открываются первым разом, когда статус/поверхность наложены в бою. Ресурсы (ЗДР/МРЛ/ЭНР/КБ) — открыты сразу, тексты `tip.res.*`.

### Состояния и события
- Хуки: `startWorldBattle` — отметить `seen` всех врагов боя; победа/«Сломлен» — `kills[id]++` (каждая запись счётчика один раз за бой); `meetFaction`, `visit`, `onTalk`, `grant`-флаг `cx-*`; статус/поверхность в событиях боя (`status`, `surfaceCreate`) — `seen` термина.
- Нормализация в `save.js`: отбрасывать неизвестные id; старые сейвы — пустой кодекс, `seen`/`kills` не восстанавливаются, фракции и места берутся из `met`/`visited`.
- Вход: кнопка «Кодекс» (K) в карте и локации; сцена `codex.js` (вкладки разделов, список слева, карточка справа, `scroll.js`).

### UI/фидбек
- Список: открытые — имя и значок фракции; закрытые — силуэт и `???` (`CODEX_UNKNOWN`). На карточке врага закрытые блоки — серые строки «Победи в бою, чтобы узнать больше» (`CODEX_HINT_LOCKED`); уровень записи — полоска «Видел → Побеждён → Изучен».
- Тост при первом открытии: «Кодекс: <имя>»; при повышении уровня — «Кодекс: <имя> изучен»; новая находка — «Кодекс: новая запись». Звук — мягкий `ui`-тик (одиночный).
- Подсказки терминов в бою/интерфейсе — как сейчас; кодекс лишь собирает их тексты.

### Критерии приёмки
1. До первой встречи враг в бестиарии — `???` без портрета; после боя — имя, портрет и лор.
2. После первой победы видны ЗДР/КБ/способности; слабости и лут — только после 5 побед над типом.
3. Вариации `X^1.5`, `X-5` и версии уровня не создают дубль записи, если у типа есть `ENEMY_LORE` (запись — по `baseId`).
4. Находка с флагом `cx-…` появляется в карточке только после установки флага; повторная загрузка сохранения сохраняет кодекс.
5. Фракции — только `isMet`; места — только посещённые; термины статусов/поверхностей — только применённые.
6. Скрипт-проверка: все ключи `ENEMY_LORE` есть в `GAME_DATA.ENEMIES`, все 14 фракций — в `FACTION_LORE` (сейчас 0 ошибок).

### Вне рамок
Награды за заполнение кодекса, ачивки, бестиарий прочих рас-союзников, поиск и фильтры, озвучка, отдельная страница заметок игрока, редактирование записей изнутри игры, лор на все 480 версий врагов (лор — на ~39 ключевых).
